2. Типові запитання викладача та точні відповіді

❓ Питання 1: Як ви підключили JavaScript до HTML-сторінки?

Відповідь: За допомогою тега <script src="script.js"></script> всередині документа index.html. Атрибут src вказує відносний шлях до файлу скрипта.

❓ Питання 2: Чим відрізняється git commit від git push?

Відповідь: git commit фіксує підготовлені зміни локально на моєму комп'ютері та створює новий знімок історії. А git push відправляє ці локальні коміти на віддалений сервер (на GitHub).

❓ Питання 3: Що робить команда git clone?

Відповідь: Команда git clone <url> завантажує повну копію віддаленого репозиторію на локальний комп'ютер, включаючи всі файли, гілки та повну історію комітів (папку .git).

❓ Питання 4: Що таке Fork і чим він відрізняється від Clone?

Відповідь: Clone копіює репозиторій на мій локальний комп'ютер. А Fork — це створення копії чужого репозиторію на стороні самого GitHub у мій власний обліковий запис. Це дозволяє вносити зміни у чужі проєкти та пропонувати їх через Pull Request.

❓ Питання 5: Як працює GitHub Pages?

Відповідь: Це безкоштовний хостинг статичних сайтів від GitHub. Він автоматично бере файли (HTML, CSS, JS) із вибраної гілки репозиторію (у нас — main) і публікує їх за адресою username.github.io/reponame.

❓ Питання 6: Як перевірити, чи спрацював JavaScript на сторінці?

Відповідь: Відкрити сайт у браузері, натиснути клавішу F12 (або комбінацію Ctrl + Shift + I), перейти на вкладку Console (Консоль) — там буде повідомлення Hello World!.

3. Ключові команди, які ви використовували

git --version — перевірка версії Git
git config --global user.name "..." — встановлення імені автора
git config --global user.email "..." — встановлення email автора
git clone <url> — клонування репозиторію
git add . (або окремі файли) — індексація змін перед комітом
git commit -m "Опис" — створення коміту із коментарем
git push -u origin main — відправка комітів на GitHub у гілку main
git status — перевірка поточного стану файлів
